TikTok Content Posting API Explained: Direct Post, Inbox Uploads and the Audit

Publishing through TikTok's official Content Posting API: OAuth with PKCE, creator info, chunked uploads, status checks and the audit.

News AI Engine Editorial Team November 21, 2026 · 4 min read

If you want software to publish videos to TikTok, there is exactly one legitimate route: TikTok’s official Content Posting API. Browser automation and unofficial endpoints break, risk your account and violate the platform’s terms. This guide explains how the official flow works, based on implementing it in our engine. API details change, so always confirm against TikTok’s developer documentation before shipping.

Two ways to post

Mode Endpoint Scope Result
Direct Post POST /v2/post/publish/video/init/ video.publish Published to the profile with the privacy you choose
Upload to Inbox POST /v2/post/publish/inbox/video/init/ video.upload Arrives as a draft; the creator finishes posting in the app

An inbox upload is not a published post. Our dashboard labels these “Sent to inbox”, never “Published”.

The unaudited-app restriction

This is the most important rule to understand before you build anything. Until your app passes TikTok’s Content Posting audit:

  • Direct Post content is limited to private (SELF_ONLY) visibility;
  • only a small number of users (five in 24 hours at the time of writing) can post through the app;
  • the posting accounts must be private.

Public posting requires applying for the audit and meeting TikTok’s UX and content-sharing guidelines. Plan for this from the start; it is not a technical problem you can code around.

Step 1: OAuth with Login Kit

Users authorise your app through TikTok’s authorise page. Desktop apps can use a localhost redirect URI with a port, and must use PKCE. Note that TikTok’s desktop flow expects the hex-encoded SHA-256 of the verifier as the code challenge.

verifier = secrets.token_urlsafe(64)[:96]
challenge = hashlib.sha256(verifier.encode()).hexdigest()
params = {"client_key": CLIENT_KEY, "scope": "user.info.basic,video.publish,video.upload",
          "response_type": "code", "redirect_uri": REDIRECT_URI, "state": state,
          "code_challenge": challenge, "code_challenge_method": "S256"}
url = "https://www.tiktok.com/v2/auth/authorize/?" + urlencode(params)

Exchange the returned code at POST https://open.tiktokapis.com/v2/oauth/token/ (form-encoded) for an access token (about 2 hours) and a refresh token (about 180 days).

Refresh tokens rotate. Each refresh returns a new refresh token and the old one stops working. Store the new token immediately, or your next refresh fails. Keep tokens encrypted at rest and never send them to a browser.

Step 2: Query creator info before every post

POST /v2/post/publish/creator_info/query/
Authorization: Bearer <access_token>

The response tells you the creator’s nickname, the privacy options they may use, whether comments, duets or stitches are disabled, and the maximum video duration. TikTok’s guidelines require you to:

  • show the creator’s nickname so users know which account they are posting to;
  • offer only the returned privacy options, with no default - the user must choose;
  • respect disabled interaction settings;
  • check the video duration against the creator’s limit.

Step 3: Initialise the post

{
  "post_info": {
    "title": "Caption with #hashtags (up to 2200 UTF-16 units)",
    "privacy_level": "SELF_ONLY",
    "disable_comment": false, "disable_duet": false, "disable_stitch": false,
    "video_cover_timestamp_ms": 1200,
    "brand_content_toggle": false, "brand_organic_toggle": false,
    "is_aigc": true
  },
  "source_info": {"source": "FILE_UPLOAD", "video_size": 26746102,
                  "chunk_size": 10485760, "total_chunk_count": 2}
}

is_aigc adds TikTok’s AI-generated content label. Our narration uses a synthetic voice, so we enable it by default.

The response contains a publish_id and an upload_url, which is valid for one hour.

Step 4: Upload in chunks

The chunk rules trip people up:

  • files under 5 MB go in a single chunk equal to the file size;
  • otherwise chunks are 5-64 MB, total_chunk_count = floor(video_size / chunk_size), and the remainder joins the last chunk (which may be up to 128 MB);
  • chunks are uploaded in order with PUT and a Content-Range header.
for i in range(total):
    first = i * chunk
    last = size - 1 if i == total - 1 else first + chunk - 1
    requests.put(upload_url, data=read(first, last), headers={
        "Content-Type": "video/mp4", "Content-Length": str(last - first + 1),
        "Content-Range": f"bytes {first}-{last}/{size}"})

TikTok answers 206 for a partial upload and 201 when the upload is complete.

Step 5: Poll the status - don’t assume success

An accepted upload is not a published video. Poll POST /v2/post/publish/status/fetch/ with the publish_id until you see PUBLISH_COMPLETE, SEND_TO_USER_INBOX or FAILED (with a fail_reason). Public post IDs appear in a field spelled publicaly_available_post_id in the API, and only after moderation. Only PUBLISH_COMPLETE means “published”.

Rate limits and caps

Initialisation endpoints allow about 6 requests per minute per user token; creator info about 20; status checks about 30. There is also a per-creator daily posting cap shared across all apps. A scheduler that spreads posts across the day, one per account at a time, stays comfortably inside these limits. See Scheduling Social Video Uploads Safely.

Errors worth handling explicitly

  • privacy_level_option_mismatch - you sent a privacy level the creator cannot use.
  • unaudited_client_can_only_post_to_private_accounts - the audit restriction.
  • spam_risk_too_many_posts - the creator’s cap is reached; try a later slot.
  • access_token_invalid - refresh, or ask the user to reconnect.
  • rate_limit_exceeded - back off.

A checklist for your integration

  • Official API only; no browser automation.
  • PKCE for desktop apps; state parameter checked and single-use.
  • Encrypted token storage; rotate refresh tokens immediately.
  • Fresh creator-info query before posting; privacy chosen by the user.
  • AI-content label when appropriate.
  • Chunked upload following the documented rules.
  • “Published” shown only after PUBLISH_COMPLETE.
  • Plan for the audit before promising public auto-posting to anyone.
