Animating News Graphics With ASS Subtitles: Typing, Kinetic Text and Wipes

Generate broadcast-style motion graphics as ASS subtitle files in Python and burn them into video with FFmpeg - lower thirds, typing and kinetic text.

News AI Engine Editorial Team November 21, 2026 · 5 min read

This tutorial shows how to generate animated graphics - lower thirds, a typing window, kinetic words and a wipe-in headline - as an ASS subtitle file from Python, and render them over video with FFmpeg. Everything here is plain text generation; no design software is required.

Graphics rendered entirely by libass from a generated subtitle file, on a neutral test background.

The ASS file skeleton

An ASS file has a header that defines the canvas, a style section and an events section. Set PlayResX/PlayResY to your design resolution; libass scales to the actual video size.

[Script Info]
ScriptType: v4.00+
PlayResX: 1080
PlayResY: 1920
WrapStyle: 2
ScaledBorderAndShadow: yes

[V4+ Styles]
Format: Name, Fontname, Fontsize, PrimaryColour, SecondaryColour, OutlineColour, BackColour, Bold, Italic, Underline, StrikeOut, ScaleX, ScaleY, Spacing, Angle, BorderStyle, Outline, Shadow, Alignment, MarginL, MarginR, MarginV, Encoding
Style: Base,Poppins ExtraBold,60,&H00FFFFFF,&H00FFFFFF,&H00000000,&H80000000,0,0,0,0,100,100,0,0,1,0,0,7,0,0,0,1

[Events]
Format: Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text

Each graphic element is one or more Dialogue: lines with override tags in braces.

Helpers you will use everywhere

def ts(t):                      # seconds -> H:MM:SS.cc
    cs = int(round(max(0, t) * 100))
    h, cs = divmod(cs, 360000); m, cs = divmod(cs, 6000); s, cs = divmod(cs, 100)
    return f"{h}:{m:02d}:{s:02d}.{cs:02d}"

def col(hex_rgb, alpha=0):      # "#D7141A" -> &H001A14D7& (ASS is alpha-BGR)
    r, g, b = hex_rgb[1:3], hex_rgb[3:5], hex_rgb[5:7]
    return f"&H{alpha:02X}{b}{g}{r}&".upper()

def dialogue(start, end, text, layer=0):
    return f"Dialogue: {layer},{ts(start)},{ts(end)},Base,,0,0,0,,{text}"

def rect(w, h):                 # vector rectangle for \p1 drawing mode
    return f"m 0 0 l {w} 0 l {w} {h} l 0 {h}"

Colours are the classic gotcha: ASS writes them as alpha, blue, green, red, and alpha 00 means fully opaque.

A lower third that wipes in

A lower third is a coloured box plus text. The wipe is an animated clip rectangle: it starts zero pixels wide and grows to the full width in 320 ms.

def lower_third(name, start, end, x=54, y=1114, width=420):
    box = (f"{{\\an7\\pos({x},{y})\\bord0\\shad0\\1c{col('#0B0B12')}"
           f"\\clip({x},{y},{x},{y+90})\\t(0,320,\\clip({x},{y},{x+width},{y+90}))\\p1}}{rect(width, 88)}")
    bar = f"{{\\an7\\pos({x-14},{y})\\bord0\\1c{col('#D7141A')}\\fad(100,200)\\p1}}{rect(14, 88)}"
    text = f"{{\\an7\\pos({x+22},{y+10})\\fnAnton\\fs75\\1c{col('#FFFFFF')}\\fad(160,200)}}{name.upper()}"
    return [dialogue(start, end, bar, 30), dialogue(start, end, box, 30), dialogue(start + 0.16, end, text, 31)]

Layers control stacking: higher layers draw on top. Keep a layer plan (background plates 30, text 31, and so on) so elements never fight.

A typing effect timed to speech

A typing window shows a statement appearing character by character. The simplest robust method is one event per step, each showing the text typed so far. Natural rhythm comes from weighting pauses after spaces and punctuation:

def typing(x, y, text, start, duration, seed=0):
    rng = random.Random(seed)
    weights = [1 + rng.uniform(-.35, .35) + (.6 if c == " " else 0) + (2.2 if c in ",.;:!?" else 0) for c in text]
    total, acc, events, shown = sum(weights), 0.0, [], ""
    prev = start
    for c, w in zip(text, weights):
        acc += duration * w / total
        t = start + acc
        if shown:
            events.append(dialogue(prev, t, f"{{\\an7\\pos({x},{y})\\fnPoppins Bold\\fs52}}{shown}", 63))
        shown += c
        prev = t
    return events

Add a blinking cursor as a separate thin rectangle that follows the end of the text, and you have a convincing “statement being typed” moment. We start typing on the word timing from our narration timeline, so the text lands as the narrator says it.

Kinetic words with overshoot

Kinetic typography makes two to five words pop in one at a time, each on its spoken word. The pop is a scale transform that overshoots and settles:

pop = "\\fscx60\\fscy60\\t(0,110,\\fscx112\\fscy112)\\t(110,200,\\fscx100\\fscy100)\\fad(40,180)"

Keep animation short (around 200 ms) and avoid bouncing more than once. Overshoot reads as energy; repeated bouncing reads as childish.

Burning the graphics in

ffmpeg -i background.mp4 -i narration.wav \
  -filter_complex "[0:v]ass=graphics.ass:fontsdir=./fonts,format=yuv420p[v]" \
  -map "[v]" -map 1:a -c:v libx264 -preset veryfast -crf 20 -c:a aac -b:a 192k out.mp4

fontsdir points libass at your bundled font files, so the output looks the same on every machine. Escape colons and quotes in the path if your filenames contain them.

Why a subtitle format works for motion graphics

It helps to think of an ASS file as a timeline of layers rather than as subtitles. Every Dialogue line has a start time, an end time, a layer number and a block of override tags that describe position, colour, size, rotation, clipping and animation. When FFmpeg renders a frame, libass draws every event that is active at that moment, lowest layer first. That is exactly the model a motion designer uses in an editing program: stacked layers that appear, animate and disappear.

Because the file is plain text, a program can write it from data. In our engine the data comes from the narration: each word has a start and end time, each development has an anchor phrase, and each person has the moment their name is first spoken. Graphics are simply that data translated into events.

Timing graphics from the narration

The most important rule for automated graphics is that they follow speech, not a fixed grid. A lower third for a person should appear when the narrator first says their name and stay for three to four seconds. A development board should appear on the first word of that development. A typing window should start typing as the sentence begins and finish slightly before the sentence ends, so the viewer reads along with the voice.

To make this work, keep one function that looks up the start time of a phrase in your word timeline, and use it everywhere. If the phrase cannot be found - because the model paraphrased it, for example - skip the graphic rather than guess a time. A missing graphic is invisible; a graphic at the wrong moment is a visible mistake.

Organising layers

Decide your layer plan once and stick to it. We use low layers for frames and background plates, the middle range for information graphics such as boards and name supers, higher layers for emphasis effects such as full-screen punch lines, and the highest layers for transitional accents. When two graphics overlap in time, the layer plan guarantees which one is on top, and a simple region check (one element per screen area at a time) guarantees they do not collide visually.

Common pitfalls

  • Wrong colour order. If your red comes out blue, you wrote RGB instead of BGR.
  • Text that does not fit. libass does not resize boxes to fit text. Measure text with the real font file and calibrate the measurement against an actual render before you draw panels.
  • Escaping. Curly braces and backslashes inside user text break override blocks. Replace them before writing the event.
  • Clipped descenders. A clip rectangle exactly one line tall cuts off the bottoms of letters such as g, p and y during wipes. Make it taller.
  • Too many events. Per-character typing for a long paragraph creates hundreds of events. That is fine for libass, but keep typing windows to one or two sentences for readability.
  • Font names. Use the family or full font name exactly as stored in the font file, and point FFmpeg at the folder with fontsdir so the render does not silently fall back to a default font.

Design rules that keep it professional

  • Two typefaces. A condensed display face (we use Anton) for headlines, a geometric sans (Poppins) for everything else.
  • A small palette. One red, one yellow, near-black panels, white text.
  • Safe zones. On vertical video, keep text out of the top ~150 px and bottom ~400 px, and away from the right edge where platform buttons sit.
  • One element per screen region at a time. Our Visual Director enforces this automatically; see Designing an AI Visual Director.
  • Measure text. Calibrate a measuring function against real libass output before laying out boxes.

Summary

ASS subtitles are a complete, fast motion-graphics system hiding in plain sight. With a dozen helper functions you can generate lower thirds, typing windows, kinetic text, wipes, pins and arrows directly from your pipeline’s data, and render them in the same FFmpeg pass as your footage.
